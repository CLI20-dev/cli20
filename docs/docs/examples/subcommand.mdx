# Subcommands

Open this when your CLI has verbs like `build`, `publish`, `run`, or `deploy`.
cli20 models those commands as nested typed schemas rather than a mutable
runtime graph.

This page is the reference for command-oriented CLIs where each verb owns its
own arguments and help output.

## What This Example Shows

This example splits one CLI into multiple verbs, gives each subcommand its own
arguments and help text, and makes it easy to check which command actually ran.
Global options are handled first, then control passes to exactly one command,
whose nested fields keep the usual `value()` and `provided()` behavior.

## Try It

<ExamplePlayground name="subcommand" defaultArgs="build --release --jobs 4 main.cc util.cc" />

Things to try:

- **build** — `build --release --jobs 4 main.cc util.cc`
- **publish** — `publish --registry https://registry.example.com --dry-run`
- **Verbose flag** — `--verbose build main.cc`
- **Subcommand help** — `build --help` or `publish --help`
- **Top-level help** — `--help`
