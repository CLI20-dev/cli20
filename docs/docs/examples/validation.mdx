# Validation

Open this example when parse-time rejection matters more than keeping to the
sugar aliases. It shows how to combine explicit conversion and validation
actions in one pipeline.

This is the page to read when you want bad input to fail early, with clear
errors, before the rest of your program starts running.

## What This Example Shows

This example converts raw argv text into typed values, rejects invalid ports and
profile names during parsing, and checks filesystem-related arguments before the
rest of the program runs. On success, the parsed state ends up as optional
typed fields for `port`, `profile`, and `output`.

## Try It

The virtual filesystem is configured like this in this environment:

```
/
└── tmp/          (directory)
```

<ExamplePlayground name="validation" defaultArgs="--port 8080 --profile release_1" setupFs={setupValidationFs} />

Things to try:

- **Happy path** — `--port 8080 --profile release_1 --output /tmp/result.txt`
- **Port out of range** — `--port 99999 --profile dev` to see range fail
- **Invalid profile** — `--port 80 --profile My-Profile` to see regex reject uppercase
- **Missing required args** — just `--output /tmp/x` to see both required args reported
- **Help** — `--help`
